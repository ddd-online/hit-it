# 低位主升候选（leader-hit）

本 SKILL 回答一个具体问题：**哪些沪深主板低价股已经具备主力低位吸筹和洗盘特征，下一步可能启动，或者已经启动但还没有进入高位兑现区？**

核心顺序固定：先圈低位，再看筹码，再看量能，再看形态，然后等市场确认，最后匹配题材。不能只凭“跌得多”“筹码好看”提前埋伏。

## 触发与边界

触发：

- 查找某价格上限内的沪深主板候选，默认 20 元以下；
- 判断一只或多只股票是否符合“建仓完成、洗盘中、待启动、启动初段”；
- 从一组股票中排除高位、筹码分散、阴跌不止或启动失败的票。

不处理：

- 下单、仓位、止损金额和账户操作；
- 创业板、科创板和北交所；
- 已经明显高位、纯情绪接力或没有市场确认的提前埋伏；
- 把日 K 推演筹码写成券商原始持仓数据。

最终标签只能使用：`建仓完成 / 洗盘中 / 待启动 / 启动初段 / 只观察 / 排除`。

## 默认参数

| 项目 | 默认值 | 用户覆盖 |
|---|---:|---|
| 价格上限 | 20 元 | 支持 `--price-max` |
| 日 K 样本 | 120 根 | 不得低于 80 根后仍判“建仓完成” |
| 左侧涨停证据 | 近 5–60 个交易日 1–4 次 | 用户可改窗口，但必须写入报告 |
| 筹码集中度 70% | ≤16% 为良好 | 推演值降级时只作辅助 |
| 上方成本 90% 高点距现价 | ≤25% 为压力较轻 | 负值表示现价在上方，需结合实际 |
| 20 日涨幅 | ≥35% 进入高位检查 | 与位置、获利盘同时看 |
| 高价位次 | 120 日区间位置 ≥75% | 不单独决定，需与阶段涨幅合看 |

用户给出的价格、窗口或阈值优先，报告中写“默认口径 / 用户覆盖项”。

## 运行流程

### 1. 先运行脚本，不手工重复算数

以下命令均以本 `SKILL.md` 所在目录为当前目录。若从项目根目录运行，请给脚本路径加上该技能在项目 `skills/` 下的相对前缀。

全市场低价主板初筛：

```bash
python scripts/prepare_leader_candidates.py --price-max 20 --compact
```

只列价格范围内的沪深主板股票，不做结构判断：

```bash
python scripts/prepare_leader_candidates.py --price-max 20 --universe-only --compact
```

判断用户指定的股票：

```bash
python scripts/prepare_leader_candidates.py --codes 600000,000001 --price-max 20 --compact
```

脚本完成：主板与 ST 过滤、行情日期、日 K、均线、箱体、量能、左侧涨停、筹码推演、技术分和初判状态。模型不得重复计算这些字段；需要审计时用 `--json`。

`--scan-limit` 默认从低价主板中选快照预排序前 120 只再拉历史行情：近期涨幅不极端、换手和成交额有效、主力净流入为正的优先。它仍可能漏掉排名外股票；需要完整覆盖时调大或设 0 扫描全部，并在报告注明扫描范围。`--compact` 只展示前 30 行，完整结果用 `--json`。

### 2. 状态硬规则

| 状态 | 最低证据 |
|---|---|
| 建仓完成 | 低位有过 1–4 次涨停吸筹；底部筹码集中；上方压力轻；尚未有效突破 |
| 洗盘中 | 涨停点火后回调 1%–18%；不破启动位；5 日量能缩至前期 90% 以下 |
| 待启动 | 箱体收敛、均线粘合、地量；筹码集中；贴近箱体上沿但尚未放量突破 |
| 启动初段 | 放量突破箱体上沿；20/60 日涨幅和获利盘尚未进入高位 |
| 只观察 | 只有部分结构成立，数据不足，或题材/消息尚未核验 |
| 排除 | 高位、筹码分散、缩量阴跌、连续一字断层、缺少左侧建仓或硬风险 |

脚本状态是结构初判，不是最终买卖结论。任何入围票都必须继续核验题材、公告和最新消息。

### 3. 做硬排除

下列任一成立即不能进入“启动初段”或重点候选：

- 非沪深主板、ST、退市整理、停牌；
- 日 K 不足 80 根，属于纯次新或时间沉淀不足；
- 近 5–60 个交易日没有左侧涨停吸筹；
- 高位筹码未消化，90% 成本区高点明显压在现价上方；
- 筹码东一坨西一坨，没有底部单峰；
- 低位放量但价格滞涨，疑似对倒出货或严重分歧；
- 天天缩量创新低，跌破近 20 日支撑；
- 连续一字板抬升，底部与现价之间出现筹码断层；
- 20 日涨幅 ≥35%、120 日区间位置 ≥75% 或获利盘 ≥92% 且阶段涨幅已大；
- 财务造假、立案、退市风险、重大处罚、业绩暴雷、正在执行的大额减持。

### 4. 补题材和消息

只对 `建仓完成 / 洗盘中 / 待启动 / 启动初段` 中技术分较高、且通过硬排除的 3–5 只做补查。使用当前运行环境可用的网页搜索、交易所公告、公司公告和主流财经媒体核验：

- 精确概念、所属板块和板块扩散；
- 近 48 小时催化、澄清、减持、解禁、诉讼、处罚和业绩风险；
- 同题材是否存在多只股票同步走强。

题材聚合优先使用精确概念，不按名称模糊匹配。最新催化必须给出标题、原始来源、发布时间和链接。没有网页检索能力或无法回溯原始来源时，消息面写“未核验”，相关股票只能“只观察”。

### 5. 顺序与优先级

先排除，再按状态和证据排序：

1. `启动初段`：已有真金白银确认，优先检查是否已追高；
2. `待启动`：结构完整，等放量突破，不提前埋伏；
3. `洗盘中`：等缩量结束、回踩不破和重新放量；
4. `建仓完成`：仅进入股票池，继续等洗盘与确认；
5. `只观察`：保留证据，不列为重点；
6. `排除`：写明唯一主要原因。

同一只票不得因为命中多个概念重复出现。技术分高但题材弱、无催化或负事件未排除的，仍然只能“只观察”或“排除”。

## 两个固定问题的输出

### 问题一：查找沪深主板 20 元以下股票

先报告价格、成交额、换手和结构状态，再列结构候选。若用户只问范围列表，可用 `--universe-only`；若问“哪些可能启动”，运行完整结构筛选并继续核验题材。

摘要必须给出：

- 数据日期、执行时间、扫描股票数和价格上限；
- 各状态数量；
- 最多 5 只重点结构票；
- 每只票的现价、状态、支持位、箱体上沿、左侧涨停次数、筹码集中度和主要排除风险；
- 扫描是否因 `--scan-limit` 截断。

### 问题二：判断指定股票

每只股票必须逐项回答：

| 检查 | 输出 |
|---|---|
| 主板与价格 | 是否通过 |
| 位置 | 120 日区间位置、20/60 日涨幅 |
| 左侧涨停 | 次数、最近日期、是否近期连续一字 |
| 筹码 | 平均成本、70%/90% 集中度、获利盘、上方压力、质量等级 |
| 量能 | 5 日量能比、突破日量能比、是否缩量洗盘 |
| 形态 | 箱体高低、均线粘合、是否守住支撑 |
| 题材消息 | 已核验 / 未核验 / 负事件 |
| 结论 | 固定状态 + 一句执行前还需看到什么 |

单只股票行情失败不能推测，写“数据未获取”；`quote_date != data_date` 时标记数据失真，不给出可执行结论。

## 数据口径

- 行情和日 K 通过技能内现有取数层获取，跨源数值不能混比。
- `data_date` 是行情实际日期，`generated_at` 是执行时间。
- 筹码是“日 K + 换手率推演值”，不是券商原始筹码。
- `metric_quality=degraded` 时筹码只能辅助，不得单独支撑重点候选。
- 东财 `f109` 与 `f160` 整批同值时，10 日涨幅按“未获取”处理。
- 报告文件固定写入 `report/主升候选/<data_date>.md`，同日重跑覆盖更新。
