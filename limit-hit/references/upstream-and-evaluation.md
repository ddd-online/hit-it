# 上游报告复用与次日高开评估

文中 D 始终指行情实际数据日期。报告文件名使用 D，不使用本机执行日期；凌晨执行时 `generated_at` 可以晚于 D。

## 1. 数据来源顺序

| 数据 | 首选 | 回退 |
|---|---|---|
| 当日涨停、炸板、跌停、晋级反馈 | 本次运行技能内 `scripts/fetch_limit_up.py --json` | 无；拉取失败就停止，不使用旧报告冒充当日 |
| 昨日涨停全名单、板数、行业、成交额、最高板、主线、阵型 | `report/涨停板复盘/` 下日期早于本次数据日的最近一份 `YYYY-MM-DD.md` | 用当日数据返回的 `prev_date` 执行 `scripts/fetch_limit_up_history.py --date <prev_date> --json` |
| 昨日个股消息、股东、筹码、洗盘路径 | 对最终入围候选重新拉取 | 不沿用昨日候选的旧个股结论 |

### 1.1 昨日报告选择

1. 取本报告数据日 D 之前最近的一份 `report/涨停板复盘/YYYY-MM-DD.md`，不要取 D 当日报告。
2. 报告日期必须与今日数据里的 `prev_date` 一致；不一致视为不可直接复用，改拉 `prev_date`。
3. 只复用报告的事实数据，不沿用报告的“主线”“阵型”作为最终结论；它们只作为背景。
4. 报告为盘中口径、字段不全或缺少涨停全名单时，可用它做索引；最终板数、成交额、首封时间和最高板须用昨日接口数据补齐，并注明“报告复用 + 接口补齐”。

### 1.2 从昨日报告取什么

| 报告节 | 取数 | 用途 |
|---|---|---|
| 涨停全名单（供次日竞价评估） | 代码、名称、板数、行业、成交额、首封时间 | 昨日样本、同题材延续、一进二/二进三反馈 |
| 连板高度与最高板 | 最高板代码、名称、板数 | 今日硬规则检查 |
| 数据概览 | 涨停、跌停、炸板、封板率 | 昨日情绪基准 |
| 当日主线板块（板块行合并表） | 板块、BK、涨停家数、资金、领涨股 | 今日题材延续判断 |
| 阵型判定 | 阵型标签 + 紧邻结构说明 | 背景参考，不机械复用 |

昨日报告缺失时，用技能内 `scripts/fetch_limit_up_history.py --date <prev_date> --json` 的 `rows` 重建涨停名单、板数、行业、成交额和首封时间；该源不含炸板池、跌停池和市场封板率，缺失内容写“未获取”，并在报告中写明“由接口重建”。

接口可以重建昨日名单、板数、行业、成交额、首封时间和最高板；昨日主线板块与阵型依赖历史板块快照和多份报告，无法重建时分别写“未获取”，不得拿今日板块或阵型倒推昨日。

## 2. 参考 limit-judge 的次日高开评估

### 2.1 集体开盘分布

对昨日涨停全样本计算：

- 高开幅度 =（今开 - 昨收）÷ 昨收 × 100%；
- 高开 / 平开 / 低开家数；
- 平均与中位高开幅度；
- 按一进二、二进三分别统计晋级率、高开率、平均开盘、平均收盘。

单只股票不作为结论。昨日样本集体低开、平均高开为负或最高板跌停时，即使局部题材强，也降低候选数量或停止输出可打板。

### 2.2 最高板硬规则

取昨日最高板代码，在今日 `yesterday_performance.rows` 或行情中核对：

- 开盘接近涨停且尾盘跌停，记“天地板”；
- 任何形式跌停，或 `close_state=跌停`；
- 行情缺失导致无法判断。

出现天地板或跌停时，本报告结论只能是“只观察”，不输出可打板。行情缺失时按“不可判定，只观察”处理。

### 2.3 次日 9:25 开盘卖出复核

本 SKILL 在 D 日盘中买入后，次日 9:25–9:30 按 `limit-judge` 口径复核开盘：

- 高开幅度：默认 +2% 至 +5% 为温和高开；>+8% 要防高开出货；
- 竞价量占比 = 次日竞价成交额 ÷ D 日全天成交额；
- 3%–8% 为活跃；>15% 警惕；<1% 视为市场不关心；
- 9:30 后运行不能把全天成交额当竞价成交额，竞价量占比标“不可用”。

报告中必须写清每个候选的成交价与 D 日成交额，作为次日退出和竞价量占比的基准；盘中未收盘时写“待收盘确认”，不得提前填最终值。

## 3. 输出要求

报告中另列“上游复用”与“次日高开评估”两节：

- 上游复用：用了哪份 `limit-find` 报告、哪些字段由接口补齐；
- 次日高开评估：昨日集体开盘分布、最高板状态、硬规则结论、每个候选的高开与竞价量占比条件。

所有结论只用于候选筛选，不处理资金、仓位或交易执行。
