# 涨停池复用与次日高开评估

文中 D 始终指行情实际数据日期。报告文件名使用 D，不使用本机执行日期；凌晨执行时 `generated_at` 可以晚于 D。

## 1. 数据来源顺序

| 数据 | 首选 | 回退 |
|---|---|---|
| 当日涨停、炸板、跌停、晋级反馈 | 本次运行技能内 `scripts/fetch_limit_up.py --json` | 无；拉取失败就停止，不使用旧报告冒充当日 |
| 昨日涨停全名单、板数、行业、成交额、封板字段、题材归属、市场概览 | `report/涨停池/<previous_date>.json` | 当日 `prev_zt_rows`；再回退 `fetch_limit_up_history.py --date <previous_date> --json` |
| 昨日个股消息、股东、筹码、洗盘路径 | 对最终入围候选重新拉取 | 不沿用昨日候选的旧个股结论 |

### 1.1 涨停池文件选择与生成

1. 昨日文件固定为 `report/涨停池/<previous_date>.json`，日期必须与今日数据里的 `prev_date` 完全一致。
2. 文件存在且 schema、日期、`stocks` 合法时直接复用，禁止覆盖。
3. 文件不存在时，优先使用当日 `fetch_limit_up.py --json` 随带的 `prev_zt_rows` 生成。
4. 当日接口没有带回昨日池时，调用 `fetch_limit_up_history.py --date <previous_date> --json` 回补并生成。
5. 文件损坏或日期不匹配时直接报错，不静默覆盖历史文件。
6. 盘后执行且 `quote_date == data_date`、时间达到 15:00 时，若当日文件不存在，生成 `report/涨停池/<data_date>.json` 供下一交易日复用。

同花顺历史接口的 `high_days_value` 只编码“几天几板”，表示统计窗口内涨停次数，不是当前连续板数。仅当“窗口天数 = 涨停次数”（如 4 天 4 板）时可确认为当前连续板；其他记录 `board_count` 必须为 `null`。东财涨停池的 `lbc`、上述等价窗口或连续交易日池成员回算结果才可进入一进二、二进三和最高板判断。

### 1.2 涨停池文件包含什么

| 区块 | 字段 | 用途 |
|---|---|---|
| `summary` | 总数、最高板、板数分布、行业分布、至少 2 只股票的题材聚合 | 模型快速读取昨日结构和主线；单票题材见 `stocks` |
| `stocks` | 代码、名称、当前板数、窗口统计、行业、价格、涨幅、成交额、换手、首封/末封、开板次数、封单、涨停统计、题材 | 昨日样本、同题材延续、一进二/二进三反馈、最高板硬规则 |
| `market` | 涨停、跌停、炸板、封板率 | 昨日情绪基准；历史源缺失时保留 `null` |
| `source` | 数据源标识、名称、生成时间、限制 | 审计与跨源口径说明 |

题材来自生成时的东方财富 F10 精确概念，历史归属可能变化，报告必须保留该限制。

## 2. 参考 limit-judge 的次日高开评估

### 2.1 集体开盘分布

对昨日涨停全样本计算：

- 高开幅度 =（今开 - 昨收）÷ 昨收 × 100%；
- 高开 / 平开 / 低开家数；
- 平均与中位高开幅度；
- 按一进二、二进三分别统计晋级率、高开率、平均开盘、平均收盘。

单只股票不作为结论。昨日样本集体低开、平均高开为负或最高板跌停时，即使局部题材强，也降低候选数量或停止输出可打板。

### 2.2 最高板硬规则

取昨日最高板代码，在今日 `yesterday_performance.rows` 或行情中核对：

- 开盘接近涨停且尾盘跌停，记“天地板”；
- 任何形式跌停，或 `close_state=跌停`；
- 行情缺失导致无法判断。

出现天地板或跌停时，本报告结论只能是“只观察”，不输出可打板。行情缺失时按“不可判定，只观察”处理。

### 2.3 次日 9:25 开盘卖出复核

本 SKILL 在 D 日盘中买入后，次日 9:25–9:30 按 `limit-judge` 口径复核开盘：

- 高开幅度：默认 +2% 至 +5% 为温和高开；>+8% 要防高开出货；
- 竞价量占比 = 次日竞价成交额 ÷ D 日全天成交额；
- 3%–8% 为活跃；>15% 警惕；<1% 视为市场不关心；
- 9:30 后运行不能把全天成交额当竞价成交额，竞价量占比标“不可用”。

报告中必须写清每个候选的成交价与 D 日成交额，作为次日退出和竞价量占比的基准；盘中未收盘时写“待收盘确认”，不得提前填最终值。

## 3. 输出要求

报告中另列“上游复用”与“次日高开评估”两节：

- 上游复用：用了哪份 `report/涨停池/<date>.json`、文件是复用还是新生成、昨日池数据源；
- 次日高开评估：昨日集体开盘分布、最高板状态、硬规则结论、每个候选的高开与竞价量占比条件。

所有结论只用于候选筛选，不处理资金、仓位或交易执行。
