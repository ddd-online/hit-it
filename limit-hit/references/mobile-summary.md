# 手机端核心摘要

报告落盘后，最终回复先给摘要，再给报告文件链接。摘要不是报告副本，只保留决策所需信息。

## 固定结构

```text
【涨停打板候选】
数据日期：YYYY-MM-DD
执行时间：YYYY-MM-DD HH:MM
口径：盘中快照 / 收盘复盘 / 盘后计划

结论：可打板 N 只 / 只观察 N 只 / 今日无可打板
情绪：涨停 N，最高 N 板，一进二晋级 X%，炸板率 X%
停牌高标：名称（代码）/ 无；同行业或精确概念排除 N 只

1. 名称（代码）
题材 / 一进二或二进三
状态：刚封 / 第 N 次回封 / 封板 N 分钟
触发：回到涨停并满足封单条件
风险：一句主要失效条件

2. 名称（代码）
……

报告：report/打板候选/<数据日期>.md
不构成投资建议
```

## 约束

- 只写最终“可打板”和最多 3 只“只观察”；排除清单只写数量和主要原因。
- 每只股票控制在 4 行以内，不用宽表格。
- 数据日期必须来自 `data_date`；执行时间来自 `generated_at`。凌晨执行时两者可以不同。
- 不写“预计高开 X%”，只写可核验事实和触发/失效条件。
- 没有可打板时，第一行直接写“今日无可打板”，不要用观察票凑推荐。
- 有停牌最高板时必须写清“停牌高标”和连带排除数，不能把停牌写成低开、跌停或行情缺失。
