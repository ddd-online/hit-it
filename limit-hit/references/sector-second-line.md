# 板块第二梯队研判

## 定位

第二梯队不是“当天涨停后的接力候选”，而是从有涨停核心、有明显扩散的精确概念中，寻找执行时点仍未涨停、但历史位置和筹码可控、当日量价开始转强、后续可能封板或取得次日溢价的沪深主板成分股。

它与打板候选是两个独立名单。一个题材可以同时有一只打板候选和一只第二梯队候选；两者不得共用名额，也不得把第二梯队写成已经买入或必然封板。

## 候选边界

- 只处理沪深主板，排除 ST、退市整理、停牌和数据无法核验的股票。
- 执行时点必须仍未涨停。已经涨停、买不到或只剩排板可能的股票归打板候选处理，不能伪装成第二梯队。
- 题材必须来自当天的精确概念聚合，并存在涨停核心、梯队或扩散；只有个股上涨、同题材不跟随的独涨现象不选。
- 默认每个入围题材最多保留一只第二梯队候选；若证据相近，宁可保留“只观察”，不要为了凑数扩大名单。
- 候选只是研究结论，不计算仓位、资金或个人盈亏。

## 数据采集

脚本提供事实，模型负责研判。不要用脚本排序、单个阈值或机械总分直接替代对盘面的理解。

1. 先运行 `prepare_candidates.py --compact`，用市场情绪、题材梯队和打板候选建立当日背景。
2. 对计划审视的题材定位精确 BK：

```bash
python limit-hit/scripts/fetch_sector_boards.py --type concept --search <题材1> <题材2> --json
```

3. 对每个 BK 获取完整成分股事实：

```bash
python limit-hit/scripts/fetch_sector_leaders.py --board BKxxxx --top 300 --json
```

`--json` 用于查看代码、名称、T 时点价格、涨跌幅、换手、量比、近 5/10 日涨幅、资金和行业；`--compact` 只适合快速看扩散摘要。

若返回行数正好等于 `--top`，不能假定已经覆盖全部成分股；扩大 `--top` 重取，并在报告写明样本边界。

4. 先通读成分股，不按单一涨幅榜机械截断。对主板、未涨停、仍在交易、同题材逻辑直接的股票做初筛，通常每个题材保留 2–5 只进入深查。
5. 对初筛股票批量补齐历史、均线和筹码：

```bash
python limit-hit/scripts/fetch_stock_metrics.py --codes sh600000,sz000001 --days 120 --workers 8 --json
```

6. 每只进入深查的第二梯队股票都必须完整走单股评估流程。默认按代码去重后，给每只股票启动一个独立子代理；同一代码命中多个题材时只评估一次，由父模型最终归入最直接的题材。子代理自行取数与判断，不接收父模型预设的结论。

```bash
python limit-hit/scripts/prepare_candidates.py --stock <代码> --json
```

子代理继续执行单股流程中的题材定位、板块扩散、新闻公告和资金核验。负面事实回查原始公告。不要只对父模型预先挑中的一只做深查，否则多股比较失去意义。

7. 父模型收集所有子代理结果后再选优。跨题材重复股票只保留一条最直接的题材归属；同一题材内只允许一只最终候选。

## 子代理逐股评估

第二梯队继承单股持仓审视的取数、六维证据和硬规则，但把持有结论转换为第二梯队候选状态。多个股评估默认一股票一子代理：

1. 父模型完成板块扫描和初筛，按股票代码去重，并冻结本批 `data_date`、快照时间和题材/BK 上下文。
2. 启动子代理时只给目标代码、相关精确题材、板块 BK 和执行批次信息，不提供希望它选出的答案。
3. 一只子代理只能评估一只股票，不得打包多股后只返回排名。
4. 子代理独立运行完整单股流程，并返回代码、名称、题材、`data_date`、`quote_date`、`generated_at`、六维事实与状态、历史涨跌、筹码质量、消息来源、硬风险、候选结论、触发、失效和数据限制。
5. 子代理不得横向比较其他股票、不得决定题材名额、不得写最终报告、不得创建观察池或其他状态文件。
6. 父模型在全部结果返回后统一检查 `data_date`、`quote_date` 和 `generated_at`，再按题材横向比较并生成最终名单。
7. 子代理数量超过环境并发上限时分批启动；不同批次必须保持同一执行时点口径。盘中数据发生跨时点变化时，重新取数或标为不可横向比较。
8. 运行环境没有子代理能力时，必须明确报告限制并询问是否允许串行。获准后才由父模型按相同流程逐股执行并注明降级原因；未获同意不得声称完成多子代理评估。

建议子代理使用以下任务骨架：

```text
使用 limit-hit 的单股持仓审视完整流程评估 <代码>。
相关精确题材：<题材>；板块 BK：<BK>；执行时点：<T>。
必须自行运行 prepare_candidates.py --stock <代码> --json，并补题材扩散、新闻公告和资金。
按价格承接、量能、筹码、题材、消息与风险、市场环境六维给出健康/临界/不健康/未获取。
最终只返回该股的第二梯队候选/只观察/排除、关键证据、触发、失效、data_date、quote_date、generated_at 和数据限制。
不要比较其他股票，不要决定题材名额，不要写最终报告。
```

父模型不能用子代理数量、状态票数或任何机械汇总代替横向判断。子代理结论冲突时回到原始事实，比较题材地位、历史位置、T 时点量价、筹码和情绪，再决定谁进入最终名单。

## 核心证据

以下四类事实同等重要，不能只看一项，也不要把它们压缩成一个伪精确总分。

| 证据 | 必须读取的事实 | 研判重点 |
|---|---|---|
| 执行时点量价 | 现价、今开、最高、最低、涨跌幅、换手、量比、成交额、价格相对开盘和日高、同板块相对强弱 | 是主动走强、承接良好，还是冲高回落、放量滞涨、尾盘诱多；盘中量能必须标“盘中部分量” |
| 市场情绪 | 涨停/跌停、封板率、炸板率、昨日晋级率、昨日集体开盘、最高板状态、题材梯队与扩散 | 题材处于点火、扩散、加速还是收缩；市场是否仍给后排溢价，核心断板时后排是否还有生存空间 |
| 历史涨跌幅 | 5/10/20 日涨幅、MA5/10/20、20 日位置、近几日量价、前期涨停或套牢压力 | 是低位转强、箱体突破，还是高位加速后追涨；上涨是否有缩量回踩和放量突破配合 |
| 筹码结构 | 获利盘、平均成本、70%/90% 成本区间、集中度、现价相对均价、股东户数及披露滞后 | 上方兑现压力是否可控，筹码是集中还是发散；`degraded` 只能作辅助，`unavailable` 不得补造 |

基本面只做地雷排查，不用营收、利润、负债率或估值给短线强弱排序。出现财务造假、立案调查、退市风险、重大违规、业绩预告暴雷、正在执行的大额减持或解禁时，直接排除或降为只观察。

## 模型研判

假设模型具备成熟短线交易经验，依据原始事实做情境判断，而不是照抄固定公式：

- 优先找“题材仍有空间、个股尚未透支、T 时点主动转强、量价与位置相互印证”的组合。
- 高开本身不是买点，封板也不是唯一价值。要区分强承接、弱转强、冲高回落和放量出货。
- 历史涨幅轻、筹码可控、板块强而个股刚跟随，通常比历史涨幅沉重、筹码松动、当日巨量滞涨更值得继续审视。
- 同题材已有高标加速时，要评估后排是被动补涨还是主升扩散；核心尚未确认、后排先掉队时，宁可只观察。
- 数据互相冲突时保留冲突，写成观察条件；不要用主观想象补齐分时、封单或资金行为。
- 消息无法核验只能“只观察”；T 时点行情缺失或行情日期不一致时停止给出候选结论。

## 执行语义

第二梯队候选对应的是“执行时点按当时可见价格研究是否介入”，不是回测中用当日开盘价补造的历史成交。

- 触发必须写明：题材继续保持扩散、个股仍处未涨停状态、价格重新站上关键承接位或放量突破、量价未出现明显背离。
- 若写“看封板”，必须给出封板前可观察的路径，例如分时承接、板块同步转强、放量突破日内高点；不能把未来是否封板当成已知事实。
- 失效必须写明：板块核心炸板/跌停、题材扩散转弱、个股跌破执行时参考位、放量滞涨、冲高后失去承接或出现负公告。
- 默认退出仍是次日开盘复核；若当日封板，则按次日溢价条件处理。报告不得承诺封板或溢价。

## 结论

第二梯队结论只能是：

- `第二梯队候选`：T 时点可执行，四项核心证据相互印证，基本面未见地雷，并写明触发与失效条件。
- `只观察`：逻辑成立但历史位置、量价、情绪、筹码或消息至少一项仍有明显冲突。
- `排除`：硬风险、独涨、停牌、非主板、已经涨停不可执行、行情缺失或结构性弱势。
