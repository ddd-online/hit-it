# 涨停打板候选（limit-hit）

本 SKILL 回答两类问题：

1. **批量筛选**：当前这批涨停股里，哪些一进二、二进三最值得打板，第二天最可能高开？
2. **单股持仓审视**：用户指定名称或代码后，这只沪深主板股票的量价、筹码、题材、消息与市场环境是否健康，究竟应继续持有、条件持有还是不继续持有？

批量候选必须把最新消息、板块梯队、题材趋势、题材内未涨停股扩散、封板质量、洗盘结构、筹码结构和当日情绪放在一起看。单股即使当日没有涨停，也要按同一证据范围审视，不能因为高开上涨就直接判健康。

## 触发与边界

- 触发：用户问今天哪些票可以打板、明天的一进二或二进三、次日最可能高开的涨停股、结合题材与消息筛打板候选。
- 用户提供股票名称或代码并问“还能拿吗、是否继续持有、量能和筹码是否健康”时，进入单股持仓审视。
- 批量候选只做 `0→1` 当日已经涨停后的 `1→2`，以及 `2→3`；三进四及以上、跌停反核、未涨停埋伏不进入批量候选。
- 单股持仓审视不要求当日涨停，当日状态可以是涨停、炸板、上涨、下跌、平、停牌或未获取；只支持沪深主板。
- 一个题材只进入一只候选。默认最多保留 3 个题材，用户可在请求中修改该上限。
- 必须在报告里给出“可打板 / 只观察 / 排除”三种状态；消息面无法核验的票不能进入“可打板”。
- 本 SKILL 只做候选筛选，不处理资金、仓位或交易执行。

## 运行窗口与前置

1. 用户可在 `09:30–11:30`、`13:00–14:30` 任意盘中时刻运行；所有字段只能取快照 T 时点已知值。
2. 历史样本中首次封板集中在 `09:30–09:35`，这是优先扫描窗口；`10:00–11:00` 仍可运行，但优先看刚封板、刚回封或强题材核心，封板已久且无新催化的票要降级。
3. 收盘后或凌晨也允许运行，用于复盘和下一交易日计划；此时必须使用最近交易日作为 `data_date`，运行口径写“收盘复盘/盘后计划”，不能把执行日期当数据日期。
4. 报告必须标“盘中快照”或“收盘复盘”及执行时间；盘中数据不能被收盘字段替代。
5. 当日涨停始终由技能内 `scripts/fetch_limit_up.py --current-only --json` 现场拉取，不拿旧报告冒充当日。
6. 昨日涨停池固定复用 `report/涨停池/<previous_date>.json`，运行时不再自行拉取、回补或生成；文件不存在时停止运行，并提示先执行 `save_limit_pool.py --date <previous_date>`。已有文件不得覆盖。历史池的“几天几板”只是窗口涨停次数，当前连板数为空时不得推算一进二或二进三。
7. 板块权限固定为沪深主板：沪市 `600/601/603/605`，深市 `000/001/002/003`；创业板、科创板和北交所股票不进入候选，并在报告注明。
8. 报告文件必须写入 `report/打板候选/<data_date>.md`：文件名日期取自 `prepare_candidates.py` 的 `data_date`，不是本机执行日期。凌晨执行、跨日执行或非交易日执行时，仍使用行情实际数据日期；同一数据日期重跑覆盖更新。脚本输出的 `report_path` 是唯一目标路径。
9. 单股持仓报告必须写入 `report/个股审视/<data_date>_<code>.md`，不得覆盖批量候选报告。

## 核心流程

### 1. 建立当日与昨日样本

每个交易日收盘后，在当前交易工作区保存当日涨停池：

```bash
python D:\github\hit-it\limit-hit\scripts\save_limit_pool.py
```

运行 SKILL 时再拉取当日实时涨停池并读取已保存的昨日涨停池：

```bash
python limit-hit/scripts/prepare_candidates.py --compact
```

默认使用 `theme-first`，即“结构分化、强梯队优先”口径：

```bash
python limit-hit/scripts/prepare_candidates.py --compact
```

`default` 当前与 `theme-first` 等价，可通过 `--profile` 显式指定；`--profile v1.4` 可复现旧口径。其他自定义 profile 仍从 `config/rules.yaml` 加载。

保存脚本默认取最近已完成交易日，写入当前目录 `report/涨停池/<date>.json`；需要补某日时使用 `--date YYYYMMDD`。`prepare_candidates.py` 一次性完成当日实拉、昨日文件读取、概念聚合、梯队统计和候选指标计算，不自动生成涨停池。模型读取输出，不重复手工拉取或计算这些字段。具体边界见 [references/runtime-context.md](references/runtime-context.md)。

数据日期、行情时间必须写进报告。接口回退日期不等于用户请求日期时，直接说明差异；不能把旧数据冒充当日。

若 `quote_date != data_date`，该批接力反馈不是当日口径，应标“数据未获取”并停止给出可打板结论。

报告“上游复用”必须写清：读取了哪份 `report/涨停池/<date>.json`、使用了其中哪些事实字段，以及昨日涨停池的来源。

### 2. 模型选择题材，再补扩散

脚本已经输出题材聚合结果。模型只负责从 `themes` 中选择值得继续看的 1–3 个题材，不重新计算涨停家数、昨日家数、晋级数或最高板。

每个题材至少满足以下一项才进入强度分析：

- 当日同题材涨停 ≥2 家；或
- 昨日已有同题材涨停，今日仍有晋级；或
- 题材内出现 2 板以上核心，且未涨停股同步走强。

先收集入围的 1–3 个题材名，只调用一次
`scripts/fetch_sector_boards.py --type concept --search <题材1> <题材2> <题材3> --json`
定位 BK 与板块行；再对每个 BK 调用
`scripts/fetch_sector_leaders.py --board <BK> --top 300 --compact` 取扩散摘要。一次传入多个题材可复用同一份板块榜单，避免每题材重复扫描。需要逐股核验原始明细时改用 `--json`。只有涨停股上涨、题材内其余股票不跟，判“独涨题材”。

题材强度与候选评分口径见 [references/selection-rules.md](references/selection-rules.md)。

### 3. 判断市场是否允许打板

先看情绪，再选个股。至少给出：

| 维度 | 必须写的数字 |
|---|---|
| 赚钱效应 | 涨停家数、跌停家数、炸板率、封板率 |
| 接力反馈 | 昨日涨停今日晋级率、平均涨幅、高开/低开家数 |
| 连板高度 | 最高板、2 板及以上家数、高度较昨日变化 |
| 分模式反馈 | 昨日一进二晋级率/高开率、二进三晋级率/高开率 |

同时按 `$limit-judge` 的口径做两项硬检查：

1. **集体开盘分布**：昨日涨停样本今天有多少高开、平开、低开，平均/中位高开幅度；单只股票不作为情绪结论。停牌股单列，不计入高开/平开/低开、平均/中位开盘、平均收盘或晋级率分母。
2. **昨日最高板**：正常交易的最高板若今天天地板、跌停或行情缺失无法判断，本报告只能写“只观察”。停牌最高板不按天地板、跌停或行情缺失处理，也不触发该条全市场只观察规则；多只最高板中只忽略其中停牌者。

情绪处于退潮或高标集体负反馈时，降低推荐数量或直接输出“今日无可打板”；不得因为某个题材好看而绕过情绪门槛。具体门槛见选择细则。

`market_gate.breadth_collapse` 只表示跌停家数宽度条件；默认 `collapse_veto=false`，它只作风险提示并降为偏弱；显式启用否决时才停止输出。`market_gate.leader_collapse` 是正常交易最高板天地板、跌停或行情缺失，任何 profile 都不能关闭。

### 4. 先做硬过滤，再深查

候选必须同时满足：

- 当日 `board_count` 为 1 或 2；板数未获取则排除；
- 沪深主板、非 ST、非退市整理、非停牌；
- 若昨日最高板停牌，排除与其同行业或共享至少一个精确概念的当日 1/2 板候选；`名称组:*` 不参与匹配；
- 默认 `one_word_executable=true`，一字板只有在板上成交额大于 0、封单未撤且数据可核验时才进入候选；未启用该口径时，全天一字只列“强度证明”。一字板不获得洗盘加分，必须输出 `one_word=true`、`board_amount_yi`、`seal_fund_yi`、`seal_fund_ratio_pct`、`seal_fund_over_float_pct`、`fill_probability`；
- 未出现财务造假立案、重大减持正在进行、退市风险、监管处罚、业绩暴雷等可核验负事件；
- 最新题材催化与个股消息通过网页搜索核验，并在报告中给出标题、来源、发布时间、链接。

脚本已先完成 1/2 板筛选、沪深主板权限过滤、停牌最高板同行业/精确概念过滤和 profile 对应的一字板过滤，再对剩余候选计算封板、量比、开盘/最低价差、历史涨跌、均线和筹码字段，并给出 `metric_quality`。排除数分别见 `board_permission_excluded_count`、`suspension_filter.excluded_count` 与 `one_word_filter.excluded_count`，不得合并。`degraded` 表示换手率与筹码使用近似值，只能作为辅助证据，不能据此认定“筹码结构优秀”。模型筛出每个题材的 1–2 只后，只补取消息与资金：

- `scripts/fetch_news.py <code> --news 10 --ann 10`：最新催化、澄清、减持、诉讼、处罚；
- `scripts/fetch_capital_flow.py <code>`：主力资金；
- `scripts/fetch_stock_structure.py <code>`：只有脚本输出缺股东户数时才补取。

A 股短线默认不把营收、净利、负债率、估值作为主要加减分项；基本面只保留硬风险检查：财务造假、立案调查、退市风险、重大违规、业绩预告暴雷、正在执行的大额减持或解禁。筹码字段是日 K + 换手率推演值，不是券商原始筹码；必须原样标注口径和 `metric_quality`。股东户数有披露滞后，作为筹码辅助证据。

### 5. 消息面搜索

最新消息是硬证据，不是可选补充。

1. 搜索题材关键词、板块新闻、候选股名称与代码；优先交易所公告、公司公告、政府/行业协会、主流财经媒体。
2. 若有停牌最高板，补查停牌核查原因及原始公告，记录标题、发布时间和链接；无法核验时写“停牌原因/公告未核验”。
3. 每条关键消息记录发布时间与链接；转述类稿件必须回溯原始来源。
4. 当前实盘只采用近 48 小时内新增催化，或近 7 日内仍在持续强化且今天有新涨停扩散的催化。更早的长逻辑可以写背景，不能单独支撑打板。
5. 当前环境没有网页搜索能力时，明确写出限制；`scripts/fetch_news.py` 只能补充公司新闻与公告，不能假装已经完成全网检索。

### 6. 打分、去重与结论

按选择细则给题材强度和个股结构分。默认题材强度须 ≥80；一进二结构分须 ≥80，二进三须 ≥79；消息硬门槛必须同时通过。先按题材强度排序，再在题材内选分最高的一只；同一代码不得因多个概念重复出现。

偏弱市场只保留 1 只。默认 `theme-first` 在候选所属题材强度 ≥80 时，把门槛改为一进二 ≥80、二进三 ≥79；题材 <80 仍按 85 分处理，数量上限始终为 1。

最终状态只能是：

- `可打板`：硬过滤通过、题材强度达标、消息可核验、候选分达到默认门槛；
- `只观察`：逻辑成立但封板质量、消息、情绪或买点条件不足；
- `排除`：硬过滤失败、题材独涨、负事件、权限不允许或数据不足。

“可打板”必须同时写出执行触发与失效条件，例如“回封且封单不低于当日成交额的 X%”“竞价高开低于 Y% 放弃”。不能只写“看好”。

执行语义固定为：**盘中在首次封板或回封时排板/买入，持有到次日开盘卖出**。如果候选已经封死且没有开板，不能把“推荐”写成“已买到”；只有实际排板成交或回封成交才算执行。次日高开达到目标后默认开盘离场，低开按失效条件处理。快照越晚，越应使用 `minutes_since_first_seal`、`minutes_since_last_seal` 和 `is_reseal` 区分“刚封/刚回封”与“封板已久的旧票”。

次日高开评估沿用 `$limit-judge` 口径：高开幅度按“次日开盘 ÷ 当日收盘 - 1”计算，竞价量占比按“次日竞价成交额 ÷ 当日全天成交额”计算。D 日只写观察条件，不用盘中全天成交额伪造次日竞价数据；盘中未收盘时，分母标“待收盘确认”。

### 7. 生成报告

按 [references/report-template.md](references/report-template.md) 的固定骨架写入报告。`可打板名单`表头不得改。

报告必须保留「上游复用」「昨日涨停今日集体开盘」「次日 9:25 开盘退出复核」三节，并单列停牌最高板过滤审计，让报告能看出昨日涨停池文件用了什么、停牌与行情缺失如何区分、最高板硬规则是否通过、连带排除了哪些候选，以及次日竞价按什么分母复核。

报告必须回显 `rule_profile.name`、`one_word_executable`、`collapse_veto` 和偏弱门槛实际取值。使用非默认 profile 时增加「用户口径覆盖」段，并写明不应用覆盖时的结果。

所有数字进表格；趋势用箭头，状态用固定标记，不用表情符号。报告结尾必须写“不构成投资建议”。

报告落盘后，必须在最终回复中再输出一段适合手机阅读的核心摘要，至少包含：

- `数据日期` 与 `执行时间`，两者不得混用；
- 市场情绪一句话；
- 每只可打板股票按“名称（代码）— 题材 — 模式 — 当前状态 — 触发 — 失效”分行展示；
- 没有可打板时，写“今日无可打板”，再列最多 3 只只观察股票及一句原因；
- 报告文件位置和“不构成投资建议”。

手机摘要使用窄屏友好的短段落或编号列表，不使用宽表格，不重复完整证据。示例见 [references/mobile-summary.md](references/mobile-summary.md)。

## 单股持仓审视

用户明确给出股票名称或代码，并询问“还能拿吗、是否继续持有、量能和筹码是否健康”时，使用单股模式。批量筛选的执行语义不自动延长；只有用户提出持仓审视，才评估是否继续持有。

### 1. 解析股票并装配事实

```bash
python limit-hit/scripts/prepare_candidates.py --stock <名称或代码> --compact
```

单股模式使用同一默认 `theme-first`；需要自定义时通过 `--profile` 指定。

- 名称必须唯一精确匹配；找不到、重名或模糊命中多只时停止，要求用户提供代码，不猜股票。
- 只支持沪深主板。创业板、科创板和北交所直接提示超出范围。
- 继续实拉当日涨停池并读取昨日涨停池，复用相同的市场情绪、昨日集体开盘、最高板和分模式反馈。
- 单股不要求当日涨停。涨停、炸板、上涨、下跌、平、停牌、行情未获取必须如实区分；不得补造 `board_count`。
- 当日涨停池中的板数、首封、开板、封单只用于解释打板背景；昨日涨停池用于说明进场日板数与次日表现。
- 盘中量比和换手来自尚未收盘的部分日数据，必须标“盘中部分量”，不能当成全天量能。

### 2. 补题材、扩散和消息

脚本输出的 `stock_review.themes` 是目标股当前精确概念。按当前流程选择目标股最直接、最强的 1–3 个精确题材：

```bash
python limit-hit/scripts/fetch_sector_boards.py --type concept --search <题材1> <题材2> <题材3> --json
python limit-hit/scripts/fetch_sector_leaders.py --board <BK...> --top 300 --compact
python limit-hit/scripts/fetch_news.py <code> --news 10 --ann 10
python limit-hit/scripts/fetch_capital_flow.py <code>
```

只对目标股补消息和资金。必须把“高开上涨”与“健康”分开：同时检查高开后是否跌破开盘、冲高回落幅度、放量滞涨、换手过热、同题材扩散、龙头/高标反馈和可核验负事件。

### 3. 健康维度与结论

每个维度只能标“健康 / 临界 / 不健康 / 未获取”：

| 维度 | 必须回答 |
|---|---|
| 价格承接 | 高开幅度、现价相对开盘与最高价、是否守住昨收和关键均线、5/10/20 日涨幅 |
| 量能 | 部分日或全天量能口径、5 日量比、相对昨日成交量、换手率、上涨放量或放量滞涨 |
| 筹码 | 获利盘、平均成本、90% 成本集中度、现价偏离均价、股东户数及披露滞后 |
| 题材 | 精确概念、同题材涨停/炸板、未涨停扩散、题材阶段与龙头反馈 |
| 消息与风险 | 48 小时内催化、澄清、减持、立案、处罚、退市和业绩暴雷 |
| 市场环境 | 涨停/跌停、炸板率、晋级率、最高板负反馈与昨日集体开盘 |

整体结论只能是：

- `继续持有`：主要维度健康，没有硬风险，原有持有条件未被破坏；
- `条件持有`：逻辑仍成立，但量能、筹码、题材、消息或盘中数据存在临界项；必须写出继续持有的触发和失效条件；
- `不继续持有`：出现硬风险、明确放量出货、筹码显著松动、题材独涨或塌陷、原失效条件触发。

消息无法核验时该维度为“未获取”，整体不得给“继续持有”。`metric_quality=degraded` 时筹码最高只能标“临界”，不能把推演值当精确证据；`unavailable` 时筹码为“未获取”。

`quote_date != data_date` 时停止给出持有结论，只写“数据未获取”。不输入成本价、不计算个人盈亏、不处理仓位和下单。

### 4. 单股报告与摘要

单股报告按 [references/report-template.md](references/report-template.md) 的单股模板写入：

```text
report/个股审视/<data_date>_<code>.md
```

报告必须保留「上游复用」「昨日涨停今日集体开盘」「次日 9:25 开盘退出复核」三节，并说明停牌最高板是否影响目标股所处行业或精确概念。手机摘要必须直接给出“继续持有 / 条件持有 / 不继续持有”、各健康维度的最重要数字、保留条件、失效条件和报告路径。

## 回测

使用技能内脚本执行结构代理回测：

```bash
python limit-hit/scripts/backtest_limit_hit.py --start 20260101 --end YYYYMMDD --capital 6000
```

默认使用 `theme-first` 的一字板可排板口径。历史涨停池没有完整日级跌停家数与昨日整体晋级反馈，`collapse_veto` 只能回显口径，不能用缺失历史数据伪造市场状态。

回测报告固定写入 `report/回测/涨停打板_<start>_<end>.md`，并沿用
[references/backtest-report-template.md](references/backtest-report-template.md)。历史消息、公告负事件、
盘中封板和板块扩散无法完整复现时必须标为“结构代理回测”，不能把结果宣传为完整 SKILL 实盘胜率。
历史池不会把“11 天 6 板”当成 6 连板；回测脚本会用请求区间前的预热交易日恢复连续板数，预热仍无法确认连板的样本不参与候选。
